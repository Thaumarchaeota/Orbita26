# Isolated PowerSync Windows probe

Synthetic experiment for `docs/plans/powersync-windows-isolated-validation.md`.
This is not application integration, a production schema, or network acceptance.
Only the coordinator runs commands. The implementor has not built or run this code.

## Isolation

- Independent Cargo workspace; SDK pinned to `=0.1.1`, rusqlite 0.39.
- Run commands from this directory so `.cargo/config.toml` uses one build job and this project's target directory.
- No endpoint, credentials, environment-driven database location or external path arguments.
- Every invocation creates a UUID directory under the OS temporary directory, including a Unicode path component, with exclusive directory/file creation. SQLite only opens files reserved by this run.
- All data and backups are synthetic. Evidence is retained on success and failure. There is no automatic cleanup, recursive removal, dataDir access, or clear/reset operation.
- Constructing a reqwest client supplies the SDK interface; this probe never calls `connect` or makes an HTTP request.
- `Cargo.lock` has been generated by the coordinator and is retained. The first build stopped because `libclang.dll` was unavailable; the second was blocked when bindgen rejected an existing Android SDK DLL as x86. These were Windows build-environment blockers, not evidence of a PowerSync defect. With an x64 libclang prepared, the third build and the single test run succeeded. The implementor has not run commands.
- The 45-second Tokio deadline is cooperative and cannot interrupt synchronous SQLite/filesystem calls. Backups additionally use explicit small steps, a five-second deadline checked between steps, and a 500-step cap. These are not hard operating-system I/O deadlines.

## Coordinator commands (not executed by implementor)

PowerShell working directory: this probe directory. Keep machine-specific paths and logs in ignored `local-results/` if recording local output here.

On Windows MSVC, the dependency's bindgen step needs an **x64 libclang C API** (`libclang.dll`) and compatible runtime dependencies; its header parsing also depends on the headers required by the binding input. A DLL's presence alone does not establish compatible architecture. This run used the PyPI `libclang` 18.1.1 `win_amd64` wheel, verified before ZIP extraction into ignored `target/libclang-pypi18-x64`. The wheel was 26,415,083 bytes with SHA256 `4dd2d3b82fab35e2bf9ca717d7b63ac990a3519c7e312f19fa8e86dcc712f7fb`; the DLL was confirmed as PE machine `8664`/x64. No global installation or persistent environment change was made. `LIBCLANG_PATH` and the matching runtime `PATH` were set only for the build process; this successful run needed no additional resource-header arguments. Other binding inputs may require matching Clang resource and platform headers. The full official LLVM 18.1.8 archive download was stopped because it was too slow; its partial archive was not used. Detailed preparation evidence is in the experiment plan.

## Evidence and limits

G1 reads actual SQLite/core versions and FULL/WAL/FK settings, and uses the real SQLite backup API.

G2 inspects actual SDK `CrudTransaction` entries, metadata and previous values. A deferred FK really fails at COMMIT; explicit rollback must restore domain table, queue and quarantine counts and leave the connection reusable.

G3 reproduces immediate FK and UNIQUE ordering counterexamples using SQL. It does **not** invoke SDK downsync. No unsafe/private apply API is used, so echo suppression and real downloaded checkpoints remain untested.

G4 implements an explicitly local experimental quarantine policy: freeze all CRUD payload/metadata/base/reason; commit rescue first; verify it; then invoke SDK `complete`. Exact frozen bytes serve as the probe fingerprint, not a production canonical hash. Duplicate identical rescue is idempotent; reused identity with different bytes fails closed and must leave rescue records and the SDK queue unchanged. Two completed groups' entire five-column rescue rows are frozen as the recovery oracle. A third real SDK group remains pending: the no-quarantine completion guard must reject it without changing its queue count, mutation identity or full entries. SDK reopen and backup restoration into a new synthetic directory must match all rescue columns byte for byte and preserve that third group's full frozen payload, SDK transaction/client IDs and base. No server accepted/rejected response is claimed.

G5 tests the real SDK single-connection lease exclusion and release, plus disconnect on a database never connected to a service. It does not test a running actor, production coordinator, root switching or epoch callbacks.

G6 is untested: real network, multi-device convergence, server validation/receipts, six-month pending, compaction, host power loss and production migrations. FULL and successful SQLite commits do not prove host power-loss durability.
