## Verified platform metadata registration helper (coordinator run completed)

The first coordinator build found the correct Gradle9.3.1 and resolved plugin dependencies, then failed to discover `android-37.0`; it did not reach Kotlin compilation. The official platform archive has `AndroidVersion.ApiLevel=37.0` and no `package.xml`. AGP9.1.1's sdklib32.1.1 legacy `AndroidVersionHelper.create()` calls `Integer.parseInt()` on that property and returns null on failure. The earlier assumption that legacy discovery could register this archive is therefore disproved. BuildTools36 legacy discovery generated its metadata, but the decimal platform API requires a different path. No version downgrade or source.properties edit is proposed.

The coordinator subsequently compiled the helper and ran it successfully: exit0, `verifiedFiles=11384`. The following Gradle attempt recognized the target and reached app Kotlin compilation. This registration result is separate from app build/runtime evidence. The existing target metadata is retained; do not rerun the helper, overwrite its output or remove evidence to make it runnable again.

`tooling/RegisterVerifiedPlatform.java` uses the already cached Google sdklib/repository32.1.1 libraries to register exactly the already verified platform archive. This is a **local metadata registration helper using an official serializer**, not an SDK Manager installation, license acceptance or successful AGP validation. It takes no arguments, derives the isolated project from its prescribed class-output path `local/register-platform-classes/`, requires the reviewed Windows JDK17 default filesystem provider, and does not use SDK Manager, remote providers, package-manager load/refresh, HTTP, deletion or a global SDK configuration. Its per-component NOFOLLOW checks reject both symbolic links and `isOther`; [JDK17 WindowsFileAttributes](https://github.com/openjdk/jdk17u/blob/master/src/java.base/windows/classes/sun/nio/fs/WindowsFileAttributes.java) explicitly includes all reparse-point attributes in `isOther`, supplemented by real-path equality checks. No extra native library is loaded by this helper.

Before its only final write it requires:

- A coordinator-fetched HTTPS copy of [Google repository2-3.xml](https://dl.google.com/android/repository/repository2-3.xml) at `local/downloads/repository2-3.xml`, parsed strictly with the same libraries' built-in schemas. The unique package must be `platforms;android-37.0`, revision2, API37.0, base extension22, referencing `platform-37.0_r02.zip`, 67,281,901 bytes and SHA1 `ed8ebf7f8822a4de5686d427f237d2fa30ff7410`.
- That exact archive at `local/downloads/platform-37.0_r02.zip` and its complete matching extracted file tree at `local/sdk/platforms/android-37.0/`. Every original file is compared to the ZIP using SHA256; extra/missing files, size differences, ZIP traversal, duplicate/case-alias entries, symlinks, reparse points and special file types are refused. No source.properties change is made.
- A read-only `checkAccepted()` of the **same parsed official license** against the specifically authorized existing SDK license location. The helper reads no global SDK packages or configuration and never calls `setAccepted`, copies accepted hashes or writes a license file. A missing/mismatched existing acceptance stops it.

It creates a fresh retained `local/platform-registration-<UUID>/` directory and calls Google's `InstallerUtil.writePackageXml()` there. All parser/serializer progress warnings and errors are fatal, including marshaling errors that the library would otherwise log and swallow. Generated XML is strictly reparsed using the same schema set and checked for the exact package identity, revision, API and original license text/hash. Only then is the previously absent platform `package.xml` written with CREATE_NEW and forced to disk; bytes are reread and strictly revalidated. An existing target, partial file or any failure is retained and is not overwritten, deleted or retried. The staging directory is also retained.

Coordinator-only compiler/runtime requirements (historical procedure; compilation and execution completed by the coordinator, not the implementor): JDK17 `javac`/`java`, no Gradle invocation. The reviewed procedure compiles only the helper with `-proc:none -d local/register-platform-classes` and runs `RegisterVerifiedPlatform` with that output directory plus the same cached library classpath; exact executed commands remain in the coordinator's record. Java source-file mode would not satisfy the fixed output-directory guard. Both processes require bounded resources and serial execution after process ownership checks. Successful compilation/execution establishes this helper's API compatibility, not the app's Android behavior.

The compile/runtime classpath can be assembled from the existing regular `*.jar` files under this project's `local/gradle-user-home/caches/modules-2/files-2.1/`, preserving the single resolved version of each artifact and excluding Gradle's transformed/instrumented cache. This reuses the existing graph and fetches nothing. Directly used libraries are `com.android.tools:repository/sdklib/common/annotations:32.1.1` and `org.apache.commons:commons-compress:1.27.1`; required cached runtime groups include Google Guava33.3.1-jre/failureaccess1.0.2, Gson2.11.0, Jimfs1.1, JAXB runtime/txw2 2.3.2 with bind-api2.3.2, activation1.2.1 and istack3.0.8, Kotlin stdlib2.2.21 and coroutines-core-jvm1.9.0, Commons IO2.16.1/Lang3.16.0/Codec1.17.1, plus the Android tools graph's dvlib/layoutlib/analytics shared/protos32.1.1 and their resolved transitive jars. ## Kotlin compilation fixes awaiting validation

The next app compilation reported `Probe.kt:103 Unresolved reference O_DIRECTORY` and `Probe.kt:136 cannot access kotlinx.serialization.json.JsonObject`. These are concrete source/dependency errors, not an Android runtime or PowerSync persistence result. The coordinator confirmed all JVMs from that build exited before authorizing this edit.

Directory durability is retained using only public Android APIs: open the directory path with `O_RDONLY`, check `OsConstants.S_ISDIR(Os.fstat(fd).st_mode)` on the actual opened descriptor, then `Os.fsync(fd)` and close in `finally`. Both `fstat` and `S_ISDIR` are public since API21, below this app's min24; no hidden numeric flag is hardcoded. [Os.fstat](https://developer.android.com/reference/android/system/Os#fstat(java.io.FileDescriptor)), [OsConstants.S_ISDIR](https://developer.android.com/reference/android/system/OsConstants#S_ISDIR(int)).

The JSON1.11.0 module metadata selects that JVM artifact. ## Experiment behavior

Application ID: `dev.orbita.powersyncprobe`. The source manifest declares an INTERNET permission removal marker to block dependency contributions; the rebuilt merged manifest and APK must confirm that no INTERNET grant remains. There is no network connector, `connect()`, queue `complete()`, data clear, backup import, arbitrary SQL/path input or external storage access. `allowBackup=false`. The app only uses its own `filesDir/powersync-synthetic-v1/` and a freshly generated UUID child. Existing evidence is retained, with no cleanup/reset button or automatic deletion.

`SeedActivity` exclusively creates the internal manifest and syncs it before SDK open, then commits two synthetic rows and a subsequent update in **one awaited transaction**. All three CRUD operations carry the same stable mutation UUID; tracking previous values makes the update retain both old fields. It asserts the full domain rows, PUT/PUT/PATCH order, complete transaction ID, each client ID, metadata, opData and old values. The complete canonical oracle and READY marker are exclusively created, file-fsynced and parent-directory-fsynced before announcing READY. WAL and FULL are checked on the writer. This does not prove hardware power-loss durability.

After READY, the application retains the open database. The coordinator must later stop this exact isolated app process, after observing READY and recording PID/process evidence. Merely destroying an Activity, ending instrumentation or calling close/reopen is not this experiment. The source deliberately performs no seed-side close.

`RecoverActivity` takes no extras or URI and only recognizes the fixed internal manifest. It validates the exact field set, protocol/SDK/core versions, canonical UUIDs, fixed database name, new process nonce, READY and oracle digest. The original database must exist and be nonempty **before** SDK construction. It never reseeds, clears, completes, explicitly migrates or substitutes a database. SDK open still performs its normal internal initialization using the identical schema. Recovery compares all public CRUD and domain fields to the original oracle, awaits safe close, then exclusively writes RECOVERED evidence and announces success. Repeated recovery refuses to overwrite an existing result. A failure leaves evidence and is reported, without automatic retry.

The activities reject caller data/extras and permit one operation per process. Activity recreation can show a refusal while the Application-owned operation continues; use the fixed log tag and durable markers as evidence. This app has no arbitrary run selector. An incomplete seed remains incomplete and blocks reseeding. Do not repair a failure by clearing/uninstalling or replacing its database.
