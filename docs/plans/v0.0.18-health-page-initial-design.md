# v0.0.18 Orbita Health：初版页面设计草案

> **状态**：讨论中；本文件记录用户提出的视觉和信息架构方向，尚不是实现授权或最终验收规格。  
> **关联**：Garmin 导入边界见 [`../adr/0008-garmin-health-initial-fetch-catalog.md`](../adr/0008-garmin-health-initial-fetch-catalog.md)。数据模型、手工 Health 记录和同步方案须在 0.0.18 数据架构计划定案后接入。  
> **设计目标**：让用户在同一 Health 页面中分别看懂「这一天发生了什么」「最近在如何变化」「这一天的关键结果」，而不把 Panel 变成管理页。

## 1. 信息架构

Health 的默认入口为 **Health 总览**。它不是“轨道页”或单一长列表，而是由三层信息构成的主工作台：

```text
每日轨道（Intraday Tracks）  → 某一天内的过程和事件
长期趋势（Daily Trends）     → 连续多日/周/月的变化
今日摘要（Daily Summary）    → 当前选中日的关键结果
```

- **轨道看过程。**
- **趋势看变化。**
- **卡片看结果。**

视觉参考是多数据时间轴与高信息密度健康摘要；不复刻任何现有产品。Panel 继续是今天的轻量仪表盘，Insight Health 承担回看、理解和管理。

**默认入口已确认**：进入 Health 时打开 Health 总览；轨道是总览的第一层，不是独立默认页面。手工 Health 记录的新增、详情和管理从总览的上下文入口进入；独立历史/管理视图是否需要另立入口待定。

**手工记录入口已确认**：总览顶部日期控件旁提供统一的「+ 记录」菜单，初版入口为餐食、午睡、手工运动、体重；血压仅预留，尚不启用。点击轨道中已有的 Meal、Nap、Weight 标记可编辑该条。Journal 的 event、mood、随记不进入此菜单。

## 2. 顶部控制

- 日期选择器：为每日轨道提供定位/聚焦日期，并控制当前日期摘要；它不是轨道数据的硬边界。
- 前一天 / 后一天：按 Health 本地日期移动。
- `7D` / `30D` / `90D` / `1Y`：只控制长期趋势的窗口，不改变当前轨道日期。

## 3. 每日轨道：共同规则

- 所有轨道共用 `00:00 → 24:00` 横轴，默认每两小时主刻度，严格时间对齐。
- hover 显示一条统一垂直时间游标与统一 tooltip；缺失值显示 `—`，不补为 `0`。
- 轨道是可横向拖动/平移的连续时间线，不锁死在当前日期的 `00:00 → 24:00`。默认以定位日期的日界为清晰参照，但可自然查看前后日期的连续数据。
- 默认主刻度仍可按两小时显示；跨日时必须显示明确日期分隔与日期标签，不能让用户误认数据仍属于同一天。
- 拖选时间段与自由缩放属于后续；初版先支持连续平移与有限、稳定的时间窗口。
- **双向联动已确认**：轨道平移时，以视口中心所在的本地日期更新顶部日期和摘要；用户选择顶部日期时，轨道直接平移到该日期的默认定位窗口，摘要同步更新。
- **默认视口已确认**：选择日期 `D` 时，轨道显示 `D-1 22:00 → D 24:00` 的 26 小时窗口。这样醒来日 `D` 的绝大多数前夜睡眠与整日行为能同屏理解；更早或更晚的数据通过连续平移查看。
- 点击睡眠、运动、餐食、喝水等事件可打开相应详情；具体交互和写入边界待定。

### Track 1：恢复 / 心肺

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Sleep | 沿时间轴的粗带 / block | 主睡眠优先；nap 用较浅小块。它是区间，不是折线。 |
| HR | 全天折线 | Garmin 图表级序列，通常约两分钟聚合；不伪装成逐秒实时数据。 |
| HRV | 弱于 HR 的夜间曲线/点 | 只显示 Garmin 实际返回的夜间数据；不补全天连续线。 |
| SpO2 | 从轨道顶部向下的 tick / 小柱 | 睡眠期可更密，白天有读数也显示；缺失留空。 |
| Respiration | 可选 overlay | 初版抓取但默认关闭，避免 Track 1 过载。 |

语义：**这一晚睡了多久，以及夜间/全天 HR、HRV、SpO2 如何变化。**

### Track 2：压力 / 能量

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Stress | 竖柱或浅面积 | 表达碎片化短期波动；运动、脱戴、数据不足的空洞必须保留。 |
| Body Battery | 平滑折线 | 表达累积能量状态；与 Stress 视觉上明显不同。 |

语义：**Stress 是即时压力，Body Battery 是剩余能量。**

### Track 3：行为 / 活动

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Workout / Activity | 有起止时间的矩形 event block | 可显示类型、名称、距离或时长；不是折线。0.0.18 只使用轻量摘要表现为时间区间，不拉 Activity/FIT 详情，也不实现详情页。点击后选中并显示简短摘要 popover；详情下钻属于后续。 |
| Steps | 日内步数柱状为主；累计线可作轻量辅助 | 同时使用两种形式时不能都抢视觉权重。日内 steps API 字段与可用性待真实 probe。 |
| Meal | 小型 marker（餐别 / fork icon） | Meal 是 Orbita Health 手工事实；点击显示详情；不接 Garmin Nutrition，避免双真源。 |
| Water | 小水滴 marker | 点击显示时间和量；日累计放在趋势和摘要，不另做 Water 折线。 |
| Nap | 浅色睡眠 block | 与主睡眠使用同一时间语义。 |

## 4. 长期趋势

- 最小粒度是「一天一个数据点」，与日内轨道严格分层。
- 窗口为 `7D`、`30D`、`90D`、`1Y`。
- 初版候选卡片：体重、静息心率、睡眠时长、夜间 HRV、日均 Stress、日喝水量。
- 后续候选：夜间平均/最低 SpO2、Body Battery 高低/充放电、HRV baseline/status。
- 体重、静息心率、睡眠、HRV、Stress 适合折线；日喝水量适合柱状。
- 血压若将来显示，只进入长期趋势（SBP/DBP 两条线或成对点），不进入日内轨道；保留 pulse、timestamp、note。

## 5. 当前日摘要卡片

当前选中日期的首批候选：

- Steps
- Sleep（时长、入睡–醒来、可选 score）
- Resting HR
- Body Battery
- Water
- Weight
- SpO2

每张卡保持：指标名、当前趋势窗口的主汇总值、该窗口的日级 sparkline / 柱，以及与**紧邻的上一等长窗口**的变化。它不使用单日相对昨天的变化；例如 `7D` 展示近七天曲线并与前七天比较，`30D` 与前 30 天比较。后续候选是 Stress、HRV、Calories、Intensity Minutes。

## 6. Garmin 获取边界

初版准备获取：

- 日健康摘要；
- 全天 HR、Stress、Body Battery、Respiration、SpO2；
- Sleep 详情与 HRV；
- Water；
- Weight / body composition；
- Blood pressure：仅可选能力探测与数据结构预留，暂不承诺 UI。

这些都须经过有界、只读 capability probe 才能成为真实可用能力。Activity/FIT 详情、Garmin Nutrition、女性健康、孕期、设备设置、成就/挑战均不在本初版。

## 7. 数据层级与缺失规则

| 层级 | 用途 | 初版对象 |
| --- | --- | --- |
| L1 Continuous / Timeline | 每日轨道 | HR、HRV、Stress、Body Battery、SpO2、Respiration、Steps time-series。 |
| L2 Interval / Event | 轨道事件 | Sleep、Workout、Meal、Water、Nap。未来 symptom、medication、caffeine、notes。 |
| L3 Daily Summary | 摘要与趋势 | steps、distance、calories、RHR、min/max HR、average stress、BB high/low、sleep duration/score、SpO2 summary、nightly HRV、water、weight。 |
| L4 Derived / Long-term | 暂不进初版主页面 | Training Readiness/Status、VO2 Max、FTP、Fitness Age、Endurance/Hill Score、Race Prediction、HRV baseline。 |

所有序列必须区分数值 `0` 与 `null` / missing。尤其是 Stress、HRV、SpO2、Respiration：

- 没有有效样本就不画任何曲线、柱、tick 或区间；不能补零、画虚线，或用前后样本跨空洞连接。
- 单个时间点没有值时 tooltip 显示 `—`。
- 不能将未佩戴、运动中未测量、接口不支持或尚未抓取混为零值。同步失败/重试反馈属于独立状态层，不得伪装成时间序列图形。

## 8. 当前待 grill 的关键决定

1. 轨道中哪些是 0.0.18 首批可见项；未完成 probe 的指标不能以模拟值占位。
2. 当前日摘要是否保留比较信息；若保留，必须与趋势窗口语义一致，不能退回“相对昨天”。
3. 同步失败或数据尚未抓取时，统一 Garmin 状态/重试入口放在哪里；不得与“没有样本”的空白曲线混淆。
4. 每种趋势卡片的窗口主值应如何聚合：例如睡眠/HRV/Stress 用平均，喝水用日均或累计，体重用最新、平均或变化。
5. 体重等离散测量在轨道中如何标示、在同日多次测量时如何选择摘要值。
