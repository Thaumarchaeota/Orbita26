## 已确认的决定

- 撤销同日拖拽：不再提供拖拽柄、插入蓝线、回弹、FLIP 动画或 `reorder-same-day` 写入。`seq` 字段和已有值保留，绝不为此改写历史账本。
- 明细仍按日期分组，UI 保持最新日期在上（`date DESC`）；账本文件保持日期正序（`date ASC`）。同一天内由有效时间排序，`seq` 是同分钟及无时间记录的稳定兜底。
- 时间只属于 transaction-level metadata：`time: "YYYY-MM-DDTHH:mm:00+08:00"`。CSV、Composer、inline 编辑继续只接受可空的 `HH:mm`（`00:00`–`23:59`）。
- 时间选择框不再显示原生时钟图标；保留 `input[type=time]`、键盘输入、分钟精度与原生值语义。
- 不迁移、不补填或静默纠正历史 `time` metadata。旧账本可继续读取；只有满足本计划“有效时间”定义的值才影响排序。

## 排序与数据契约

### 有效时间

仅当条目是 Transaction，且恰有一个 `time` metadata，值严格为
`YYYY-MM-DDTHH:mm:00+08:00`，并且日期部分等于 transaction `date` 时，才得到有效的 `HH:mm` 排序键。

读取已有账本时，不规范或日期不一致的单个 `time` 必须原样保留并视为“无时间”，不得猜测、改写或删除；它不能阻断用户保存其他无关改动。所有 Orbita 写入入口（CSV、Composer、inline）始终严格产生规范值。重复 `time` 是例外：Candidate 必须阻断保存并给出可定位诊断，因为当前 renderer 不能透明保留同 key 的多个 metadata；不得借渲染去重而静默丢失数据。

### 统一比较器

所有层必须实现同一语义，而不是各自临时排序：

1. 日期；UI 倒序，文件正序。
2. 同日的有效 `HH:mm`；UI 和文件都按时间正序。
3. `seq` 的**数值**顺序，而不是字符串顺序（因此 `a2` 必须早于 `a10`）。
4. `source_line` / 原始稳定顺序仅作最终稳定兜底，不生成或改写数据。

同日同时存在“有时间”和“无时间”时，有时间记录在前、无时间记录在后；无时间组内部按数值 `seq ASC` 和稳定兜底排序。这会让历史无时间记录的 UI 顺序与原来的 `seq DESC` 展示不同，但与规范文件顺序和 CSV“正序”一致。该规则必须同时写入 UI、Parser、Candidate 和 Commit 的比较器测试，不允许仅由某一层决定。

这不是把整个列表做一次简单反转：UI 的日期组从新到旧，但每个日期组内部从早到晚；账本文件的日期从旧到新，日期组内部也从早到晚。UI 比较器只服务展示，Candidate/Commit 比较器只服务规范化落盘；提交后 authoritative reload 必须重新得到相同的 UI 顺序。

## 验收

> 自动化验证已于 2026-08-22 实际运行；真实窗口和跨进程流程保留未勾选。

- [ ] TypeScript：日期倒序、同日时间正序、同分钟 `seq`、`a2/a10`、无时间、Pad/Balance、筛选/CSV merge/时间修改后顺序。
- [ ] Python Parser：有效时间参与展示；单个异常历史 metadata 原样保留、视为无时间且不阻塞读取；Pad/Balance 位于当日无时间组。
- [ ] Candidate：重复 `time` 拒绝且不丢数据；单个异常历史 `time` 可随无关编辑 transparent round-trip；所有新 UI/CSV 时间仍严格合法。
- [ ] Metadata：未知重复 key round-trip 后数量、顺序和值不变；重复 `time` 的时间编辑被拒绝且 Candidate 阻断，任何路径都不静默删除 metadata。
- [ ] 字符串安全：含引号、反斜杠和边界字符的 payee、remark、metadata 经过 candidate/commit/reload 后值不变；不支持的既有写法得到诊断而不落盘。
- [ ] `seq`：已有 `a9`、`a10` 时连续创建/CSV 导入不撞号；同分钟和无时间组在 commit/reload 后保持数值顺序。
- [ ] 并发安全：validate 后修改 write target、`account.bean`、`category.bean` 或 write target 设置，再 commit 必须拒绝且文件保留外部版本；结构非法的 candidate 返回诊断而非服务端异常。
- [ ] 隔离落盘：CSV → staging → candidate → atomic commit → reload；验证 UI 日期倒序、同日时间正序与文件日期/时间均正序，且 reload 后 UI 顺序不变；候选/commit hash 一致，失败不写文件。
- [ ] UI：没有任何可拖拽入口或重排序写入；时间图标不遮挡文字；真实 Tauri 中创建、编辑、CSV、保存、重载与重开均通过。

## 已确认的混排规则

同一天内，先按有效时间由早到晚排列；没有有效时间的历史记录统一置于当天最后，并按既有数值 `seq ASC` 稳定保留。未来所有记录都有时间后，该兼容分支自然不再影响结果。
