# v0.0.18 Orbita Health：初版页面设计草案

> **Outcome（设计收束，2026-09-02；代码基线 `0.0.17-snapshot`）：**本设计作为 0.0.18 Health 总览的 UI 输入已结束；已实现范围和未完成的 L3 / 用户手验以同版本的归档实施计划为准。它不再是 0.0.19 的活动实现输入。

> **状态**：已归档的 Health UI 设计输入；实施范围、数据安全与验收见 [`v0.0.18-journal-health-sqlite-foundation.md`](v0.0.18-journal-health-sqlite-foundation.md)。
> **关联**：Garmin 导入边界见 [`../../adr/0008-garmin-health-initial-fetch-catalog.md`](../../adr/0008-garmin-health-initial-fetch-catalog.md)；数据模型、Panel 保持的手工 Health CRUD 与同步方案见 [`v0.0.18-journal-health-sqlite-foundation.md`](v0.0.18-journal-health-sqlite-foundation.md)。
> **设计目标**：让用户在同一 Health 页面中分别看懂「这一天发生了什么」「最近在如何变化」「这一天的关键结果」，而不把 Panel 变成管理页。

## 1. 信息架构

Health 的默认入口为 **Health 总览**。它不是“轨道页”或单一长列表，而是由三层信息构成的主工作台：

```text
每日轨道（Intraday Tracks）  → 某一天内的过程和事件
长期趋势（Daily Trends）     → 连续多日/周/月的变化
今日摘要（Daily Summary）    → 当前选中日的关键结果
```

- **轨道看过程。**
- **趋势看变化。**
- **卡片看结果。**

视觉参考是多数据时间轴与高信息密度健康摘要；不复刻任何现有产品。Panel 继续是今天的轻量仪表盘，Insight Health 承担回看、理解与分析。

**默认入口已确认**：进入 Health 时打开 Health 总览；轨道是总览的第一层，不是独立默认页面。总览只负责回看与分析，不承担手工记录的创建、编辑、删除、跳转或详情下钻；这些既有操作继续留在 Panel。

## 2. 顶部控制

- 日期选择器：为每日轨道提供定位/聚焦日期，并控制当前日期摘要；它不是轨道数据的硬边界。
- 前一天 / 后一天：按 Health 本地日期移动。
- `7D` / `30D` / `90D` / `1Y`：只控制长期趋势的窗口，不改变当前轨道日期。

## 3. 每日轨道：共同规则

- 所有轨道共用横轴，默认每两小时主刻度，严格时间对齐；三轨各为独立圆角卡片，左侧 per-track 图例、右侧 plot；共享时间网格与 hover 游标叠在卡片栈上（竖线不穿过卡片间隙）。
- hover 显示一条统一垂直时间游标与统一 tooltip；缺失值显示 `—`，不补为 `0`。
- 轨道是可横向拖动/平移的连续时间线，不锁死在当前日期的 `00:00 → 24:00`。默认以定位日期的日界为清晰参照，但可自然查看前后日期的连续数据。
- 默认主刻度仍可按两小时显示；跨日时必须显示明确日期分隔与日期标签，不能让用户误认数据仍属于同一天。
- 拖选时间段与自由缩放属于后续；初版先支持连续平移与有限、稳定的时间窗口。
- **双向联动已确认**：轨道平移时，以视口中心所在的本地日期更新顶部日期和摘要；用户选择顶部日期时，轨道直接平移到该日期的默认定位窗口，摘要同步更新。
- **默认视口已确认**：选择日期 `D` 时，轨道显示 `D-1 22:00 → D 24:00` 的 26 小时窗口。这样醒来日 `D` 的绝大多数前夜睡眠与整日行为能同屏理解；更早或更晚的数据通过连续平移查看。
- 轨道事件首版只提供 hover 的名称、时间和已有摘要；不做点击、编辑、删除、跳转或详情下钻。
- **图例交互**：图例始终存在，首次进入时全部指标默认开启。每轨左栏为 per-track 图例；除 SpO2 外均为 **Lucide 线条图标 + 指标色**，SpO2 为 **lungs 图标 + 绿–黄–橙–红渐变描边**（与 tick 色阶一致）。点击某项后变灰并隐藏对应图形；状态跨日期与再次进入 Health 保留。统一 tooltip 只显示仍开启的指标。

### Track 1：恢复 / 心肺

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Sleep | 沿时间轴的粗带 / block | 主睡眠优先；nap 用较浅小块。它是区间，不是折线。 |
| HR | 全天折线 | Garmin 图表级序列，通常约两分钟聚合；不伪装成逐秒实时数据。 |
| HRV | 弱于 HR 的夜间曲线/点 | 只显示 Garmin 实际返回的夜间数据；不补全天连续线。图例开关与睡眠联动（无独立 HRV 图例项）。 |
| SpO2 | 从轨道顶部向下的 tick / 小柱 | 睡眠期可更密（约每分钟），白天有读数时多为小时点；缺失留空。tick **长度**：100≈顶端小点，90≈满长，越低越长。**颜色**：按数值绿–黄–橙–红渐变；**图例**为 lungs 图标 + 同色渐变描边。 |
| Respiration | 可选 overlay | 初版抓取但默认关闭；浅青绿细线，绘制层级低于 HR。 |

语义：**这一晚睡了多久，以及夜间/全天 HR、HRV、SpO2 如何变化。**

### Track 2：压力 / 能量

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Stress | 竖柱 | 按 0–100 整柱着色：低应力淡黄、高应力深橙；脱戴/空洞留空。 |
| Body Battery | 平滑折线 | 表达累积能量状态；与 Stress 视觉上明显不同。 |

语义：**Stress 是即时压力，Body Battery 是剩余能量。**

### Track 3：行为 / 活动

| 数据 | 表现 | 规则 |
| --- | --- | --- |
| Activity | 上 1/3：绿色时间区间条 | Garmin/手工活动；按视口 UTC 裁剪；显示运动类型（中文标签）；不拉 FIT 详情。 |
| Steps | 中 1/3：细柱（区间增量）+ 蓝色累计折线 | 柱为相邻样本差分；折线为 `steps_cumulative`。 |
| Meal | 下 1/3：浅橙 pill（Lucide 刀叉 + 中文餐次） | DOM 叠层绘制；`slot` 显示为早餐/午餐/晚餐/其他；不接 Garmin Nutrition。 |
| Water | 不在本轨道 | 只在长期趋势与当天摘要显示。 |
| Nap | 不在本轨道 | Nap 归 Track 1 的睡眠区间，与主睡眠使用同一时间语义。 |

## 4. 长期趋势

- 最小粒度是「一天一个数据点」，与日内轨道严格分层。
- 窗口为 `7D`、`30D`、`90D`、`1Y`。
- 初版固定为一行四张等宽复合面板：恢复（睡眠/HRV/SpO2）、身体与能量（体重/记录能量平衡）、喝水、Stress。每个子指标有独立纵轴，共享日期轴。首次仅同步近 7 天；切换到更长范围时只展示本地已有数据，并提供明确的「获取更多历史」操作，绝不自动拉取一年。
- 后续候选：夜间平均/最低 SpO2、Body Battery 高低/充放电、HRV baseline/status。
- 体重、静息心率、睡眠、HRV、Stress 适合折线；日喝水量适合柱状。
- 血压若将来显示，只进入长期趋势（SBP/DBP 两条线或成对点），不进入日内轨道；保留 pulse、timestamp、note。
- 趋势卡显示当前窗口的主汇总值、日级 sparkline / 柱，并与紧邻的上一等长窗口比较；例如 `7D` 对比前 7 天，`30D` 对比前 30 天。它不使用“相对昨天”。

## 5. 当前日摘要卡片

当前选中日期的首批候选：

- Steps
- Sleep（时长、入睡–醒来、可选 score）
- Resting HR
- Body Battery
- Water
- Weight
- SpO2

当天摘要还必须包含能量卡：**已记录摄入 / Garmin 消耗 / 记录差额**。0 餐表示“未记餐食”，不作为摄入 0，也不进入能量差额平均；趋势显示有餐食记录的天数覆盖度。

趋势中睡眠、HRV、Stress、喝水等取窗口日均，体重取窗口最新一次测量；当前日摘要只显示选中日的实际值。轨道图例始终存在；从未在本机出现的指标不显示摘要卡，曾出现但当天缺失时显示 `—`。趋势面板仅在当前窗口至少有两个有效日点时显示。

## 6. Garmin 获取边界

初版准备获取：

- 日健康摘要；
- 全天 HR、Stress、Body Battery、Respiration、SpO2；
- Sleep 详情与 HRV；
- Water；
- Weight / body composition；
- Blood pressure：仅可选能力探测与数据结构预留，暂不承诺 UI。

这些都须经过有界、只读 capability probe 才能成为真实可用能力。Activity/FIT 详情、Garmin Nutrition、女性健康、孕期、设备设置、成就/挑战均不在本初版。

## 7. 数据层级与缺失规则

| 层级 | 用途 | 初版对象 |
| --- | --- | --- |
| L1 Continuous / Timeline | 每日轨道 | HR、HRV、Stress、Body Battery、SpO2、Respiration、Steps time-series。 |
| L2 Interval / Event | 轨道区间 / 事件 | Sleep、Nap、Workout、Meal。未来 symptom、medication、caffeine、notes。 |
| L3 Daily Summary | 摘要与趋势 | steps、distance、calories、RHR、min/max HR、average stress、BB high/low、sleep duration/score、SpO2 summary、nightly HRV、water、weight。 |
| L4 Derived / Long-term | 暂不进初版主页面 | Training Readiness/Status、VO2 Max、FTP、Fitness Age、Endurance/Hill Score、Race Prediction、HRV baseline。 |

所有序列必须区分数值 `0` 与 `null` / missing。尤其是 Stress、HRV、SpO2、Respiration：

- 没有有效样本就不画任何曲线、柱、tick 或区间；不能补零、画虚线，或用前后样本跨空洞连接。
- 单个时间点没有值时 tooltip 显示 `—`。
- 不能将未佩戴、运动中未测量、接口不支持或尚未抓取混为零值。同步失败/重试反馈属于独立状态层，不得伪装成时间序列图形。

## 8. 已确认同步与仍开放问题

同步状态统一位于总览顶部日期控件附近：成功显示最后成功同步时间并可手动同步；同步中显示进行状态；失败在同处重试。它不与曲线缺失混淆，也不分散到每条轨道。

仍待 probe 或产品决定的事项是：实际首批启用哪些轨道指标、体重同日多次测量的摘要取值，以及睡眠统计的具体指标。不得使用模拟值占位。
