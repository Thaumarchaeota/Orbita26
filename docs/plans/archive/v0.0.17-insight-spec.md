## 1. 目标与不做事项

Insight 是 Orbita 的深入回看、整理、管理和分析界面，不是一次性 tab 容器。它应像成熟桌面客户端一样：切换即时、已打开内容保留上下文、异步工作不污染新视图；同时保留各领域独立的模型和数据边界。

### 1.1 本轮目标

1. 将当前“切换领域即 `unmount → 清空 admin-content → mount`”改为长期存在的 Insight Host。
2. 保留左侧栏，令其成为可扩展的工作空间导航，而非只容纳四个临时 tab 的耗空间容器。
3. 使 Health、Journal、Finance、Work 四个领域根在首次访问后缓存；切换只激活/停用，不销毁 DOM、滚动、局部路由或内存会话。
4. 保留无系统标题栏的窗口、全局设置与现有窗口控制边界。
5. 为未来真实存在的最近视图、保存视图、Context 或对话提供 UI 接入点，但不预造这些产品、数据模型或空入口。

### 1.2 明确不做

- 不新增 Health、Journal、Work 的业务功能；它们可继续是领域根/占位根。
- 不实现对话、AI 工作会话、Context、Relation、自定义视图、最近项目、跨领域首页或万能 Timeline。
- 不把不同领域数据压成共同 Event 模型，不因为侧栏统一就共享领域 Store。
- 不拆分 Tauri 应用、不恢复系统标题栏、不引入 iframe、Web/NAS 或移动端路线。
- 不在本轮引入缓存淘汰、跨窗口同步或动态工作空间条目的持久化模型。

## 2. 不可破坏的窗口与全局边界

```text
Orbita（单一 Tauri 进程）
├─ Orbita Panel（main）
└─ Orbita Insight（admin，隐藏后复用同一 webview）
   └─ Insight Host
```

- Insight 是同一 Tauri 应用中的 `admin` webview；关闭语义是 `prevent_close() + hide()`，再次打开只 `show()+focus()`，不得 destroy/rebuild。
- 窗口保持 frameless：`decorations: false`。必须继续使用 Insight 自绘标题栏；左侧 drag region 可拖动，右侧最小化/最大化/关闭区是明确的 non-drag interactive region，永远不可被 drag 覆盖。
- 右上角窗口控制必须继续自绘，不得改回系统标题栏或系统控制按钮。
- 全局设置保留在自绘标题栏，属于 Insight Host，不属于 Health、Journal、Finance 或 Work。
- 现有 main/admin 运行时图标一致性、透明窗口 click-through 和弹层交互恢复规则继续有效。

所有对话框/confirm 都使用全局 `#orbita-modal-root` 和既有 motion 生命周期。confirm 必须全局单例；弹层打开时保证原生窗口可点击，关闭后才恢复 click-through。不得把 backdrop 临时插入任意领域 root、body 或普通内容区。

## 3. Host 信息架构

```text
Insight Host
├─ Custom titlebar
│  ├─ app identity / drag region
│  ├─ global settings
│  └─ custom window controls
├─ Workspace sidebar
│  ├─ Core domains
│  │  ├─ Health
│  │  ├─ Journal
│  │  ├─ Finance
│  │  └─ Work
│  └─ Future workspace section (only when real destinations exist)
└─ Content viewport
   ├─ cached Health root
   ├─ cached Journal root
   ├─ cached Finance root
   └─ cached Work root
```

### 3.1 左侧工作空间栏

- 左侧栏保留，四个核心领域始终可见，使用其用户可见名称：健康、随记、财务、工作。
- 它可以保持现有折叠能力：展开时显示名称；折叠时显示图标并提供可访问的名称/tooltip。折叠不销毁任何领域根。
- 当前只渲染核心领域区。未来工作空间区只有在存在真实、已定义的数据来源和目的地时才显示；不可用“开发中”的对话、Context 或自定义视图占位填充空白。
- 未来条目属于导航目的地，不等于 Archive 的统一数据对象；Host 不拥有其领域数据、关系语义或持久化方案。
- Sidebar 的激活状态只反映当前 destination。选中态、焦点和键盘可达性由 Host 统一管理，不由领域页面自行修改。

### 3.2 首次进入与恢复规则

- Host 保存当前 dataDir 范围内的最后一个已成功激活 destination，以及该 destination 自己提供的可恢复位置。
- Insight 再次显示时恢复缓存的当前 destination，不重新 mount。
- 在 Host 新建且有保存状态时，先恢复上次 destination；没有有效状态或目标不能激活时，进入 Finance Dashboard。
- 本轮不创建空的 Insight Home/Overview。未来跨领域首页只有在具有真实数据、依据与产品定义时才能取代该 fallback。

## 4. Destination 注册与生命周期

### 4.1 Host 与领域的职责边界

Host 只管理导航、根容器、激活状态、共享 chrome、共享弹层和生命周期；每个领域继续管理自己的路由、数据、滚动、错误和业务 UI。Finance 保持自身 Shell / Layout / Chrome / Store / Surface 分层，不能因被 Host 缓存而把账本状态移到 Host。

实现可使用 registry，但不得再以固定的 `AdminTabId` 联合类型和单一 `unmountActive` 作为扩展边界。至少需要表达以下语义：

```ts
type InsightDestination = {
  id: string;                       // 核心领域目前为 health/journal/finance/work
  kind: "domain" | "workspace";
  label: string;
  icon: string;
  mount: (root: HTMLElement, ctx: InsightHostContext) => InsightDestinationHandle;
};

type InsightDestinationHandle = {
  activate: () => void | Promise<void>;
  deactivate: () => void;
  getRestoreState?: () => unknown;
  restoreState?: (state: unknown) => void;
  dispose: (reason: "host-dispose" | "data-dir-change") => void;
};
```

接口的内部命名可不同，但以下语义不可删减。

### 4.2 缓存规则

1. Host 为每个首次访问的 destination 创建独立 root，调用一次 `mount()`，并缓存 root 与 handle。
2. 领域切换先 `deactivate()` 当前 handle，再隐藏当前 root；随后显示目标 root。首次目标需先 mount，再 restore，再 activate。
3. `deactivate()` 只能暂停与隐藏当前领域的可恢复交互，例如 observer、轮询或焦点状态；不得清空 DOM、Store、滚动或未保存工作副本。
4. `activate()` 负责安全刷新当前可见性所需的 UI，但不得重置未保存工作副本，也不得让已过期的异步响应写回。
5. 只有 Host 真正销毁或 dataDir 切换时才调用所有 cached handle 的 `dispose()`，移除 listener/observer/timer/pointer capture，清空 roots 与恢复状态。
6. 普通侧栏切换、Insight hide/show、侧栏折叠都绝不触发 `dispose()`。

### 4.3 脏状态与离开

- Finance 存在待保存工作副本时，切换到其他顶级领域不提示、不自动提交、不丢弃；Finance root 被缓存，回到它时原样恢复。
- 真实应用退出仍由 Finance 的未保存保护阻止无提示离开。
- dataDir 切换前必须运行未保存变更保护：若用户未明确完成受控处理，取消切换；不得静默丢弃或把旧根工作副本写入新 dataDir。
- Host 不解释领域是否“脏”；领域通过显式 guard/handle 告知 Host 能否进行 dataDir 切换或退出。

## 5. Viewport、异步与样式边界

- 现有 `admin-content` 演变为 Host 的 content viewport，而非一次性 mount 点。它只负责容纳 cached destination roots，不保存领域业务状态。
- 每个 root 使用 `hidden`/等价可访问状态切换；只有 active root 可交互和参与可见布局。不得用 `innerHTML = ""` 清除 inactive root。
- Host 和领域的异步请求都必须携带 generation 与/或 `AbortController`。destination deactivate、dispose、dataDir 变化、目标 root 变化后，旧回调不得修改当前 UI 或 Store。
- 领域 CSS 必须限制在自身 root；不得以全局 ID、body 样式或 sibling selector 覆盖 Sidebar、标题栏或其他领域。
- 普通内容不竞争 `z-index`；弹层通过全局 portal；Finance 自身继续用 `isolation: isolate`。
- Host 可使用轻量切换反馈，但动效不得依赖清空 DOM，也不得延迟目标领域的交互或掩盖加载失败。

## 6. 与 Finance 的集成契约

- Finance 注册为 `finance` destination；Insight 打开时仍按既有生命周期 fire-and-forget 地异步 ensure Finance Service，且 Host 显示不能等待该过程。该 ensure 不依赖 Finance 是否是当前 destination；首次 Finance activate 只连接/呈现已有的 Service 状态。
- Finance loading、未就绪和连接失败都在 Finance root 内呈现，不替换整个 Insight viewport，也不阻断其他领域切换。
- Finance 的 Dashboard / 明细 / 统计 / 导入 keep-alive 是**领域内部**层级；Host 只缓存 Finance root。两层缓存各自负责各自的滚动与生命周期，不能互相直接操作 DOM。
- Finance 的 dataDir 变化、Service 重连和候选保存状态仍遵循 `v0.0.17-spec.md`；Host 只提供正确的 lifecycle 与变更通知。

## 8. 实现纪律

- 不得为了做可扩展侧栏而提前定义 Conversation、Context、Relation、Archive 通用对象或持久化 schema。
- 新 destination 只能在拥有明确产品语义、数据所有者、生命周期和验收标准后注册。
- 保留领域独立性：Host 是界面与生命周期层，不是数据层、全局领域 Store 或万能路由模型。
- 窗口、弹层、dataDir、sidecar 生命周期与脏状态的代码附近必须留下简短注释，解释不可破坏边界并链接本规格。
