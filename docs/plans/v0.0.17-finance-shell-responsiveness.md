## 1.5 Live decision log — Finance workspace redesign

### Confirmed

1. Finance 顶栏仍是 `admin-content` 内、横跨明细与右栏的吸顶共同顶栏；它不跨左 Admin 导航，也不应成为独立悬浮白卡。
2. 顶栏回归轻量页面 chrome：面包屑/标题与少量全局动作。筛选不再作为桌面端常驻顶栏控件。
   - 导入与筛选均从顶栏移走：导入位于右栏“添加”模块，筛选位于右栏“筛选”模块。顶栏保留返回/“资产·明细”、保存、左右侧栏开关，并预留 Finance 搜索入口。
   - “资产·明细”独立居中，默认仅文字；hover/focus 才显示轻背景与底边。点击该标题或按 `Ctrl/Cmd + F`，在标题正下方弹出居中搜索浮层，不撑高顶栏、不挤动列表。
   - `Ctrl/Cmd + F` 打开顶栏搜索框。搜索仅在当前已由右栏结构化筛选得到的列表中查找；不得改变列表集合、排序、滚动状态或右栏筛选状态。顶栏显示范围、命中序号/总数、上一个/下一个与关闭；上/下一个仅定位到相应交易，命中字段做轻量高亮，非命中条目保持原样。
   - 搜索范围固定为“全部（默认）/ 收款人+摘要 / 账户 / 标签 / 金额”。“全部”只索引上述业务结构字段及币种；不得索引 Beancount 语法、flag、link、内部 metadata、`orbita-id` 或其他实现字段。日期与时间仍使用右栏结构化筛选。
   - 搜索的结果单位为交易：同一交易即使多个字段命中也只计一个结果；定位到该交易时，其全部命中字段同时轻量高亮。
   - 文本按连续内容精确匹配；匹配前统一大小写并忽略空白字符，不做拼音、错别字或相似度猜测。
   - 点关闭或按 `Esc` 清空关键词、范围、命中高亮和当前命中位置；下次 `Ctrl/Cmd + F` 从空搜索开始。右栏筛选始终不受影响。
   - 键盘与按钮等价：`Enter` 到下一个命中，`Shift + Enter` 到上一个，`Esc` 关闭，`Ctrl/Cmd + F` 聚焦或重新打开搜索。
   - 搜索使用预规范化的本地业务字段索引；键入只更新搜索状态、命中计数与当前已渲染卡片的高亮，不得触发 Parser、服务端请求、列表筛选/排序、全量 reconcile 或重新测量。组合输入期间不计算，结束后在下一帧合并一次计算。
   - 搜索浮层显示最多 6 个业务字段值补全项；点击或键盘采用补全项后填入关键词并立刻更新命中，但不自动定位。`↑/↓` 移动补全项，`Tab` 采用当前项并保留输入焦点，`Enter` 有补全项时先采用它、否则定位下一个命中；`Shift + Enter` 定位上一个；`Esc` 先收起补全、再次按才关闭搜索。
3. 右栏保持宽屏占位式工作台，不覆盖、不挤压明细主体；明细主体固定最大宽度，只用 FLIP 重居中。全局感知流畅规则仍由 ADR 0003 约束。
4. 右栏从上到下同时显示三个模块，而非一级 tab 切换：
   - **筛选**：日期范围、类型、账户多选与标签多选；金额筛选暂不实现。
   - **添加**：并列的“+ 记一笔”与“导入 CSV”两个启动动作；它们不是带独立内容区的 tab。
   - **校验**：承载余额核验与后续受控统计；具体第一版语义尚未决定。
5. 新建交易的完整 Composer 改为受管理 modal/dialog，不再常驻右栏。
   - 日期分组标题旁的 `+` 打开 Composer，并预填该分组日期。
   - 右栏“+ 记一笔”默认预填 Asia/Shanghai 的今天；若当前筛选精确到单日，则预填该日。
   - 不提供空日期或隐式日期 fallback。
6. 当前 Finance 主区是**编辑页**，不是未来浏览明细页。核心字段应“默认文本化、点击即原位编辑”，不能为了美观把字段折叠到难以找到的二级入口。未来浏览页可另立计划。
7. 绿色勾只在原子 Commit 已确认后出现；reload、统计、测量后台运行，generation 防止旧结果覆盖新编辑。
8. 校验模块的渐进规则：校验账户只能单选；选择账户后显示该账户的余额核验，选择日期范围后在余额核验之外再显示该范围内的期间统计。
   - 校验账户只可从资产与负债/信贷账户中选择；它不是通用账户分析器，收入、费用、权益等账户不进入此控件。
   - 无日期时，余额表示当前已落盘真源的最新余额。
   - 有日期范围时，余额按范围截止日（`dateTo`；单日即该日）解释；期间统计按闭区间 `dateFrom..dateTo` 解释。
   - 有日期范围的首版统计固定展示：期初余额、流入、流出、净变动、期末余额与交易笔数；不暴露泛化 Beancount Query，也不扩展为任意账户报表。
   - 校验区提供“跟随筛选日期”开关，默认开启：校验直接使用筛选区的日期范围并自动刷新。关闭后才显示校验自己的独立日期范围；两套日期控件不在常态同时出现。
   - 未选择账户时，不请求或展示“全账本校验/统计”，避免把范围不明的数字伪装为结果。
9. 筛选模块的账户可多选，并提供明确匹配开关：默认“任一账户”（OR，交易命中任一已选账户即显示）；可切换为“同时包含”（AND，交易必须包含全部已选账户）。开关与已选账户共同构成可见筛选状态。
    - 选择父账户时自动包含全部子账户；控件应明确显示“含子账户”。筛选、单账户余额核验与期间统计统一采用此口径，避免父账户选择与其子账户数据脱节。
    - 账户选择器采用可搜索的层级树，树内勾选，不设账户数量上限。已选账户较少时以可移除标签显示；较多时显示前几个标签与“+N”/“已选 N 个账户”摘要。匹配开关紧贴账户条件，不另设筛选确认步骤。
    - 本轮不做金额筛选。拆分交易、多币种与转账的“交易金额”口径须在未来独立计划中先行定义，不能以最大分录或隐式换汇规则仓促上线。
   - 筛选即时生效，没有“应用筛选”按钮。账户搜索框的键入不触发刷新，只有选择、移除或切换条件才刷新；列表刷新应保留可行时的滚动位置。校验若跟随日期则在后台重算，不能阻塞列表更新。

10. 本轮只改变“记一笔”的呈现入口：将既有 Composer 从右栏置入受管理弹窗；字段、默认值、校验、草稿、状态机、Candidate → 原子 Commit → 绿色成功状态，以及所有既有提交后流程均不改。
    - 弹窗 UI 固定提供“取消 / 保存 / 保存并继续记一笔”。取消不写入；保存沿用既有提交动作；“保存并继续记一笔”只在同一成功动作后按已定保留规则开启下一张表单，不能新建第二套写入或保存语义。
    - “保存并继续记一笔”成功后，下一张表单保留日期、时间、类型和账户；清空收款人、备注、标签与金额。
    - 普通“保存”成功后关闭 Composer 弹窗；“保存并继续记一笔”成功后保留弹窗并打开下一张预填表单。
    - 未改动的弹窗表单可直接通过遮罩、`Esc`、关闭按钮或“取消”关闭；已有未保存输入时，所有关闭路径统一请求“继续编辑 / 放弃”确认，防止误丢草稿。
11. 扩展/提取受控的可调用输入原语：`AccountTreeMultiPicker`、`AccountSelect`、`DatePicker`、`TimePicker`。现有 `mountAccountPicker` 与 `DatePicker` 仅覆盖 Composer/旧表单所需的单值能力，尚不满足以下新合约；它们只负责统一呈现、可访问性、浮层定位、输入格式与即时校验，不得持有筛选、校验、Composer 草稿或落盘状态。
    - `AccountTreeMultiPicker` 只服务账户筛选：提供普通级联复选树与父账户包含子账户的范围语义。
    - `AccountSelect` 只服务校验与 Composer 的精确单账户目标：只能选择实际存在、当前场景允许的账户，树中父级目录只用于导航/分组，不能作为聚合目标选择。Composer 仍按现有交易类型决定允许账户与字段语义。
    - `DatePicker` 与 `TimePicker` 在筛选、校验与 Composer 之间统一 UI；对外值仍分别为既有 `YYYY-MM-DD` 与严格 `HH:mm`，时区/metadata/写入链路不因组件提取而改变。
    - 筛选与校验的日期范围使用单一触发器：在同一日历浮层内依次选择开始日与结束日，不再并排放置两个独立日期输入框。
    - 日期范围第一击立即按该日作为单日范围生效，日历保持打开；第二击才扩展为起止范围。
    - 筛选初始日期范围为“全部时间”（无日期限制），不得默认截断为本月或其他相对区间。
    - 日期范围浮层提供“今天、近 7 天、本月、今年、全部时间”快捷范围，并始终保留任意起止日的手选能力。
    - `TimePicker` 不使用浏览器原生时钟图标；提供小时选择和 `00 / 15 / 30 / 45` 分钟快捷面板（`:60` 统一表示下一小时的 `:00`，不作为可写入值）。同时保留直接键入任意严格合法 `HH:mm` 的能力，不能把既有时间精度限制为 15 分钟。
    - `TagPicker` 使用可搜索的单层平铺选择器，和账户树分开实现；标签可无限多选、默认“任一标签”（OR），可切换为“同时包含”（AND）。已选较多时显示前几个标签与“+N”摘要。搜索框、平铺选项、选中态、空状态、最大高度、隐藏滚动条与键盘行为应沉入 `SearchableSelectPopover`，但该基础件不承载标签业务语义。

12. 校验结果只对应一个账户，不做多账户结果列表。无日期时直显该账户余额；有日期时以紧凑的 2 列 × 3 行直显期初、流入、流出、净变动、期末、笔数，不另设折叠详情。
13. 右栏顶端在共同顶栏下固定，并采用独立纵向滚动作为内容过高时的保底。滚动条必须永久视觉隐藏且不占布局宽度，避免从无溢出切换到可滚动时内容横向跳动；滚轮、触控板与键盘滚动仍须可用。日历与账户树必须是有最大高度的浮层，不占右栏文档高度。
    - 仅在右栏确有上下溢出时，于可继续滚动的一端显示轻微渐隐提示；提示不占宽度、不参与布局，也不伪装成滚动条。
    - 桌面右栏固定宽度为 360px；其开合只改变舞台可用空间，明细主体仍保持既定最大宽度并按感知流畅规则重居中。
    - 窄屏沿用既有右栏抽屉容器，内部仍保持“筛选 / 添加 / 校验”三段；不另造一套 Finance 筛选界面。标题触发的搜索浮层贴近顶部并自适应可用宽度。

14. 类型筛选保留现有六项多选（支出、代支出、收入、转账、还款、未分类）与“全部”重置；右栏以 2 列 × 3 行的可勾选网格呈现并保留类型色条。未分类不占独立类别色，恢复为卡片底色/无色条语义；其选中状态由复选框与选中表面表达。

15. 右栏“添加”模块是一行两个视觉同权的启动按钮：“+ 记一笔”与“导入 CSV”；二者均不在右栏嵌入表单或导入流程。
16. 左 Admin 栏与 Finance 右栏默认均展开；本轮不新增或改变其跨重开持久化语义，已有行为保持不变。
17. “筛选”模块标题右侧在任一条件生效时显示“重置”文字按钮；点击后恢复全部时间、全部类型、无账户、无标签。无筛选条件时该按钮不显示。
    - 校验保持“跟随筛选日期”时，重置会使其回到当前余额并移除期间统计；不额外弹确认。用户可先关闭跟随开关以使用独立校验日期。
18. 支持命名、可复用的筛选预设：保存日期范围、类型、账户及其 OR/AND、标签及其 OR/AND；不保存顶栏搜索词、校验账户或校验日期。日期快捷范围保存相对语义，手选范围保存绝对起止日。
    - 筛选标题提供“预设”下拉：选中即即时应用；支持“保存当前筛选为…”与删除已存预设。
    - 修改预设不另做编辑器：先应用该预设、直接在右栏调整条件，再执行“更新此预设”。
    - 删除预设不弹二次确认：立即删除并提供短暂“撤销”提示。
    - 保存时若预设名称已存在，明确让用户选择“更新原预设 / 换个名称”；绝不静默覆盖。
    - 首版不支持“启动时自动应用默认预设”；每次进入 Finance 仍从全部时间、全部类型、无账户、无标签开始，预设仅由用户主动选择。
    - 预设只存入按当前账本工作区隔离的配置文件，沿用既有 settings/config 归属；绝不写入 `.bean` 或账本版本历史。
19. 不同筛选组之间一律取交集（日期 AND 类型 AND 账户条件 AND 标签条件）；只有账户组与标签组的内部成员分别使用其 OR / AND 开关。
    - 账户多选采用普通级联复选树：勾选父账户会勾选整棵子树，取消父账户会取消整棵子树；子账户可独立勾选，父账户据此显示全选、半选或未选。筛选状态保存实际勾选的账户集合，不引入“父账户减去子账户”的隐式排除语义。
20. 筛选预设有独立、纯本地的配置校验层，不进入账本 Candidate/Commit：
    - 配置文件加载并取得账户目录后，后台校验全部预设并标记“需修复”；不阻塞 Finance 首次展示，也不改写用户配置。
    - 保存预设时同步校验其日期、类型、账户引用和 OR/AND 值；不接受无效配置。
    - 用户选择预设时再次即时校验，账户引用不可用则阻止部分应用并列出原因，允许编辑或删除；绝不静默跳过条件。
    - 账户结构变更后使校验结果失效并重新校验。标签即使当前没有命中也不视为损坏，因为它可以是未来会再次出现的业务标签。
21. 校验统计不引入通用多币种估值或隐式换汇：普通单币种账户仍显示一组紧凑指标。对 Visa 等外币消费，posting 明确写有 `@@` 时，期间流入/流出/净变动直接采用其写明的总价与币种（如 `@@ 700 CNY` 即为 `700 CNY`）；没有 `@@` 时按原币种（如 USD）分行显示，不使用 `@` 或历史交易推导汇率。账户余额始终按实际持仓币种显示。
    - 统计文案按账户根类型适配：资产账户使用“流入 / 流出 / 净变动”；信贷账户使用“消费 / 还款 / 欠款变化”。期初、期末与交易笔数保持共用含义。
22. 新增全局、主题适配的 `LoadingIndicator` 原语，统一加载几何、速度、reduced-motion 与无障碍状态；提供按钮内的紧凑样式与内容区的局部样式，但不做全屏阻断 loader。现有 `action-motion` 的按钮 pending spinner 应迁移/复用其核心视觉，禁止每个页面另造转圈。
    - 校验账户或日期变更时，账户选择控件保持可见，结果区使用内容区 `LoadingIndicator` 与柔和占位过渡；不得保留或伪装上一次账户的结果。请求以 generation 防止过期响应写回。

### Explicit non-goals

- 不在本轮改 CSV、时间排序、`seq`、Parser、Candidate、Commit 或账本落盘契约。
- 不将桌面右栏改为覆盖主区的 drawer。
- 不以“金额筛选”这一名称掩盖双式分录中未定义的金额语义。

### Open questions — grill in order

1. 金额筛选未来究竟匹配哪一层：任一 posting 的绝对值、所选账户 posting、Expense/Income posting，还是报告币种经济金额。
2. 编辑卡片布局本轮保持不变：它服务于接近 `.bean` 的字段关系与原位编辑。未来若新增独立阅览模式，再以单独计划设计浏览卡片的信息层级与视觉语言。

### Known implementation fact

当前 `/api/stats` 是 Orbita 自建的无参数余额/断言聚合，并非通用 BQL/query endpoint。若校验加入账户或日期范围，必须新增受控参数和明确返回模型，不能直接暴露任意 Beancount Query。

## 1. Goal and non-goals

### Goal

使 Finance 壳层在左 Admin 导航和右“记一笔”栏开关、保存成功及后台刷新时保持视觉连续：明细主体不逐帧改变宽度或重排；绿色勾在账本原子 Commit 成功后立即出现；后续刷新不阻塞用户继续编辑。

### Non-goals

- 不改 CSV、时间排序、`seq`、Parser、Candidate、Commit 的数据契约或账本渲染顺序。
- 不改左 Admin 导航和右记一笔栏的产品归属，不将它们改为覆盖明细的 drawer。
- 不以提前显示绿色勾伪造未持久化的成功。
- 不重写 CardDetailSurface、虚拟列表或 Finance 状态机以外的无关模块。

## 2. Accepted product contract

```text
左/右栏状态改变
  -> 外层可用空间一次切换
  -> 固定宽度的明细主体只从旧中心 FLIP 平移到新中心
  -> 不逐帧扩宽、不拉满、不被覆盖

validate / candidate / Commit 进行中
  -> 进行中反馈
Commit 已确认原子落盘
  -> 立即绿色勾，可继续编辑
  -> reload / 统计 / 列表测量在后台继续
后台刷新失败
  -> 保留绿色勾 + 非阻塞“已保存，刷新失败 · 重试”
```

- Finance 顶栏属于 `admin-content` 内的共同顶端，横跨明细主列和右侧记一笔栏；不跨左 Admin 导航。它吸顶、无独立白色悬浮卡、仅用底部分隔线。
- 桌面端的起始日期、截止日期、类型三个筛选控件常驻顶栏中段；移除单独“筛选”开关和可折叠筛选层。窄屏才退化为“筛选”按钮和按需展开的面板，且顶栏不得换行或撑高。
- 明细主体使用既定最大宽度，不因任一侧栏收起而拉满。侧栏收起后，扩大的是舞台；主体只重居中。
- 绿色勾的语义是“核心写入已持久化”，不是“所有派生刷新已经完成”。

## 4. Implementation sequence

### A. Establish reusable layout-motion boundary

1. 在 UI 层新增小型 FLIP 工具（只处理单轴位置）：记录标记主体的旧 `getBoundingClientRect()`，一次切换状态类，读取新位置，应用反向 `translateX`，下一帧过渡回 `translateX(0)`。
2. 工具必须尊重 `prefers-reduced-motion`，并在 `transitioncancel`、连续开关、元素卸载时清除内联 transform/监听器。
3. FLIP 的目标只允许是固定宽度的内容 frame，不能是卡片列表的每张卡或虚拟列表内部节点。为 Finance 指定稳定 data-role/class，避免 Admin shell 依赖 Finance 私有 DOM 结构。

### B. Move and restyle the Finance top bar

1. 在 `finance-detail-shell.ts` 中把 `finance-chrome-topbar ledger-page-topbar` 从 `finance-chrome-main` 提升到 `ledger-page` 根，放在 `ledger-page-stage` 前。
2. 桌面端将既有 `buildFilterInner()` 的起始日期、截止日期、类型多选直接挂到顶栏中段（标题/返回之后、导入/保存/右栏开关之前）；复用已有 filter store、日期输入和 type listbox，不复制筛选逻辑。
3. 删除桌面 `filterBtn`、`FILTER_OPEN_KEY` 及 `finance-chrome-filter` 的开关状态；筛选条件本身就是可见状态。存在条件时仅显示紧凑“清除”操作，不额外塞筛选数量 badge。
4. 窄屏定义明确 breakpoint：当顶栏无法同时容纳标题、两个日期、类型与右侧操作时，才显示“筛选”按钮。它打开的面板必须复用同一组筛选 DOM/状态，不能生成第二套控制器；关闭面板不清除已选条件。
5. 保持现有标题、导入、保存和右栏开关的事件与可访问性属性；只调整 DOM 归属、响应式可见性与 CSS。
6. CSS 将顶栏设为 Finance 根内 `position: sticky; top: 0`，高于 stage/rail，使用 `admin-content` 背景和底部 1px 分隔线；移除圆角、阴影、外部留白等独立白卡效果。筛选控件须紧凑但可键盘访问，类型下拉层级高于 sticky 顶栏且不被 rail 裁切。
7. stage 的可滚动区域从顶栏下缘开始；右栏顶端与主列对齐。窄屏现有抽屉和 scrim 语义保持不变。

### C. Make both sidebars logically instant and visually smooth

1. 左栏：`admin-shell.ts` 在切换 `is-sidebar-collapsed` 前后调用通用 FLIP 边界；`admin-shell.css` 移除 `.admin-sidebar` 的 width transition。52px/200px 仍是最终逻辑宽度，但不在 200ms 内插值。
2. 右栏：`finance-detail-shell.ts:setRailOpen()` 在桌面宽度下改为“捕获 → 一次设置 `is-rail-collapsed` → FLIP 主内容”。删除依赖 `transitionend` 监听 `--ledger-rail-col` 的 layout-lock 释放方式，改为 motion 完成或取消时释放。
3. `ledger.css` 删除桌面 Grid 列和 gap 的 transition；保留最终两列/一列布局。若 rail 需要可见过渡，仅对 rail 内容用 `transform`/`opacity`，不能覆盖主内容，不能改变主列宽度。
4. 固定 `--ledger-main-max`（或等价显式 frame）作为明细视觉主体的最大宽度；左右栏开关前后断言其 inline size 不变，只改变 x 坐标。不要将主体设为 `width: 100%` 来填满新增空间。
5. 继续保留窄屏 `<1180px` 的 drawer/scrim 交互，因为该模式本来就是空间不足时的不同产品形态；本计划只修桌面重排动画。

### D. Decouple durable commit from background refresh

1. 保留 `validate -> candidate -> atomic Commit` 前置链。Commit 返回失败时仍无绿色勾，保留原有可行动错误和工作副本。
2. Commit 成功后立即以已提交 candidate 建立本地 clean baseline、触发绿色勾，并在下一帧开始成功动效；不得等待 `loadDetail(true)`。
3. 为 Detail store 引入明确的 work generation：任一用户编辑/新保存递增 generation。Commit 后启动的 reload 只在 generation 未变化时才应用 authoritative snapshot；否则丢弃该快照并不覆盖新工作副本。
4. `reloadBalanceAudit()` 改为非阻塞启动，沿用/补全其 generation 保护；错误只更新局部刷新状态和重试入口，不能阻塞绿勾或把已保存改回失败。
5. 检查 `onBeforeReload` 的删除动画：不得再 await 高度/max-height 折叠来延迟核心完成。可以淡出/平移，但逻辑移除和后台 reload 不得为此等待。
6. 成功动效保持短暂（目标 450–600ms），但时长不是正确性机制；只在 Commit 成功后启动。
