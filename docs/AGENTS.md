# Orbita 协作规则

> 风险分级与 ADR 背景见 [adr/0005-shared-worktree-agent-collaboration.md](adr/0005-shared-worktree-agent-collaboration.md)。文档维护与归档见 [README.md](README.md)。

开始实现前，阅读 [README.md](README.md)、[GLOSSARY.md](GLOSSARY.md)、[CURRENT.md](CURRENT.md)、[DECISIONS.md](DECISIONS.md) 与当前 `plans/` 计划。
涉及架构、数据目录、Journal、Finance、Service、窗口或外部集成时，额外阅读 [SYSTEM.md](SYSTEM.md)；涉及 Finance 或 Journal/Health 的实现时，同时阅读 `specs/` 中对应规格；需要运行或排错时阅读 [DEV.md](DEV.md)。

`README.md` 是文档维护和计划归档规则的唯一来源；不要在本文件复制文档维护细则。代码改动如改变当前事实、计划状态、长期约定、可复用故障处理或重大决策，按 README 更新相应文档。

文档判断的默认规则：局部 bug、样式或布局修复不写 docs；影响当前真实行为或风险写 `CURRENT.md`，当前计划的验收结果写该 plan，已定的长期护栏写 `decisions/`，重大事故/错误路线写 `HISTORY.md`，领域数据或行为契约写对应 `specs/`，新功能或跨模块范围先建 plan。只更新最小必要文件，详见 README。

代码注释解释“为何如此”和不能破坏的边界，不复述代码字面含义。涉及数据写入/迁移、兼容层、窗口或 sidecar 生命周期、并发/时区、外部服务限制，以及已否决的替代路线时，必须在代码邻近处留下简短注释并链接相关 docs；普通直观代码和纯样式不为凑注释而注释。

未经用户明确允许，禁止创建 Git commit、提交、推送、改写历史或其他 Git 写操作。

每次完成代码修改后，必须运行 `orbita/dev.bat`，等待启动过程完成并确认无报错，方可结束对话。`orbita/dev-web.bat` 只能用于中途快速预览，不能替代结束前验证。未经用户明确要求，不运行 `cargo check`、`npm run build`、`tauri build` 或其他 build 命令。

不得修改或提交 `docs_legacy/`、`reference/`、用户数据、凭据、token、缓存或本机配置。不得因审查建议而回退 `DECISIONS.md` 中已否决的方案；如需改变，先写新计划并完成真实验证。

## 共享工作树、测试与进程护栏（P0）

本仓库由用户、Cursor、Codex 及其子代理共享同一工作树和同一台 Windows 主机。任何会话都必须假定另一个会话可能正在编辑、编译、运行 `dev.bat` 或执行测试；资源安全优先于“尽快跑完”。

### 风险分级与独立角色

- **L0**：仅限用户已明确指定的颜色、尺寸、间距、文案、图标等纯视觉值；不改事件、ARIA、键盘、popover/dialog、状态、动画、性能、窗口、数据或生命周期。主 agent 可直接实现，无需 subagent。
- **L1**：局部行为、事件、ARIA、键盘、popover/dialog、状态或动画改动；至少一个实现 agent 与一个独立测试/审阅 agent。实现 agent 可补紧邻回归；测试 agent 只在独立分配的测试文件内补反例/边界，不改实现文件。
- **L2**：跨模块状态、异步/rAF/idle、筛选、滚动、性能渲染、窗口行为或服务调用；至少独立的实现、测试、验收三个 subagent。验收 agent 必须从需求和 diff 独立取证；有证据的 P0/P1 会阻止完成，主 agent 必须修复、反证或在产品/权限问题上交由用户决定。
- **L3**：数据写入、并发修改、进程生命周期、迁移、认证、凭据或用户数据；在 L2 三角色外增加独立架构/安全审计。主 agent 只协调、整合证据和运行动态命令，不计入上述独立角色。
- 任何 agent 发现任务碰到更高等级触发器，必须停止该范围并报告；主 agent 决定升档、重新切分或向用户请求产品/授权决定。主 agent 可随时因风险主动升档。

1. **运行前先确认所有权。** 在启动 `vitest`、`npm test`、`dev.bat`、Playwright/Chromium、Python API 测试或任何预计超过数秒的命令前，先检查当前工作树状态、已有开发会话及命令行含 `vitest`/`tinypool`/`vite`/`tauri` 的进程。发现已有同类任务、来源不明进程，或无法确认其是否属于自己时，停止；不得再启动第二轮、不得用清理脚本“试试看”。向用户报告占用与下一步。
2. **Vitest 全局独占。** 同一工作树任一时刻只能有一个 `vitest run`。常规完整回归只可运行 `npm test`（它必须经 `scripts/test-session.ps1` 的 Job Object）；定向 `npx vitest run <file>` 仅在已确认没有 Vitest/Tinypool 后才可由当前协调者启动。不得并行启动多个定向测试、不得让子代理、后台终端或重试逻辑各自启动 Vitest，也不得绕过配置中的运行锁或提高 fork 数。
3. **测试必须收尾。** 每轮测试后必须等待命令根和所有 `vitest`/`tinypool` 子进程退出，并按命令行复核为零，才可启动下一轮或声称测试结束。工具/终端仅提前返回、只有部分输出、超时或根进程退出都不等于测试结束；仍存活的 worker 必须按失败处理并先收束。测试失败、卡住或被用户中断时，禁止自动重试、循环重跑或立即换参数重跑。
4. **只精确处理自己可证明的进程树。** 清理前必须读取 PID、父 PID、开始时间与完整命令行；只可结束命令行明确属于本仓库且属于当前/已确认失控测试会话的根 PID 及其子树。禁止按进程名批量杀 `node.exe`、`python.exe`、`cargo.exe` 或浏览器；禁止结束来源不明的用户/其他代理进程。清理后立即复核没有 `vitest`/`tinypool` 残留，并向用户说明精确范围。
5. **开发会话同样独占。** `orbita/dev.bat` 的 mutex 是保护，不是可绕过的错误。若提示已有会话，不得启动第二个 `dev.bat`、`dev-web.bat` 或调用 `dev-clean`；先确认已有会话的根命令和用户意图。只有为本次验收确有必要且已核对为 Orbita 的旧会话时，才可停止该受管根树后重启。
6. **子代理可实现，但不得自行制造运行负载。** 协调者可将明确、互不重叠的文件范围交给子代理实现、审阅或编写测试；子代理必须保留其他会话的改动，完成后报告改动范围和未验证项。未经协调者明确、单独授权，子代理不得运行测试、启动 dev/server、启动浏览器自动化、后台任务或任何会派生进程树的命令。需要动态验证时，只能由一个指定协调者串行执行；不得以“独立验证”为由启动同类命令。
7. **出现资源压力时先止损。** CPU、内存、鼠标或网络明显受影响时，立即停止当前已确认的测试根树，不继续编译、不继续启动新测试，也不把卡顿归因于 Orbita UI 而不看进程树。先记录证据（命令行、PID、父子关系、CPU/内存、开始时间），确认恢复后再做单一、受限的复现。
8. **禁止制造重试风暴。** 脚本、代理和手工命令不得在测试/编译失败后无限或高频重试；重试必须有显式上限、退避、前一轮完整回收检查和可见错误。外层自动化不得同时拥有多条测试命令。
9. **交接必须写清运行态。** 完成、暂停或把任务交给另一会话时，必须说明：是否有活跃 dev/test/server、其根 PID/命令归属、已验证的范围、尚未完成的命令；绝不把“绿字/已启动”写成“已完成”。必要时按 README 更新 `CURRENT.md`/`DEV.md` 的真实状态。
10. **分派先列变更边界。** 主 agent 分派前必须明确“允许修改”“禁止修改”“只读参考”文件/目录；子代理只能在其允许范围内写入。涉及窗口、进程、数据写入、并发或共享 UI 原语的实现，必须先有独立审阅结论，主 agent 才可分派实现。
11. **验证按矩阵而非绿字。** 每项非 L0 改动在实现前要声明所需的证据层：单元、定向集成、真实 `dev.bat`、人工 Tauri 验收；未运行或无法运行的层必须在交付中明确为未验证。单条绿测、编译开始或 Vite ready 都不能替代其他必需层。
12. **陌生改动即冲突。** 发现目标文件已有未归属改动、未追踪文件或与分派范围重叠的编辑时，立即停止写入，列出重叠块、可能归属和风险；不得覆盖、格式化、暂存、回退或假定那是自己的旧改动。
13. **故障先广播再继续。** 出现卡顿、残留进程、端口占用、异常重启或资源压力时，主 agent 必须先在当前协作状态中记录时间、根 PID、命令、已停止范围和是否允许继续验证。其他会话看到该状态后不得启动进程，直到主 agent 明确解除。

## 行为边界

- 先证据，后重构：改架构、数据模型、窗口、sidecar、集成或交互前，必须先读相关的当前状态、计划和已定案；不能仅因代码审查建议重做已否决方案。
- 不擅自扩范围：只改用户要求或为其必需的文件；不顺手重构、不批量格式化、不删除旧代码、旧文档或用户数据。
- 真实状态纪律：未经真实验证，不得将任务标为 `[x]`，也不得声称修复或完成；方案改变用 `[-]`，未做保持 `[ ]`。
- 数据安全优先：不得静默迁移、覆盖、删除或重建 `dataDir`、journal、bill、token 或缓存；涉及迁移、覆盖或其他不可逆写入，必须先获得用户明确许可。
- 不掩盖错误：不得吞掉异常、伪造成功或用 fallback 掩盖失败；错误应保留可行动的信息和正确排查入口。
- 公开仓库卫生：新增文档、日志、示例或配置前，排除真实路径、个人数据、账号、token 与 Cookie。
- 产品决策权限：遇到会改变产品语义、交互口径、数据归属或未来路线的选择，停止实现并向用户说明选项；不得替用户作产品决定。
